# WaferGuard 데모 가이드 — 에이전트 기능 전체 시연

> **핵심 메시지(한 문장):** WaferGuard는 DNN 정확도 데모가 아니라, **"상황 판단 → 증거 검색(RAG) → 품질 리스크 해석 → 대응 조치"** 를 자율 에이전트가 수행하고, 사람·다른 에이전트와 협업하며, 운영하면서 스스로 학습하는 **에이전트 운영 시스템**이다.

이 가이드는 우리가 구축한 에이전트 기능을 **하나의 사건(ETCH-02 Scratch 반복 결함)** 으로 꿰어 보여주는 시연 시나리오다. 기능을 나열하지 말고 **사건의 생애주기**를 따라가며 자연스럽게 드러내는 것이 핵심.

---

## 0. 시연되는 에이전트 기능 (체크리스트)

| # | 기능 | 어디서 보이나 | Act |
|---|------|--------------|-----|
| 1 | 단일 검사 파이프라인 (판단→이미지→RAG→리스크→Action Card) | 실시간 검사 > 검사 결과 | 1 |
| 2 | **벡터 RAG** (embed→cosine→rerank, 메인 플로우 통합) | 검사 에이전트 > AI 추천 "근거" 모달 | 1 |
| 3 | **검사 에이전트 라이브 실행** (ReAct 루프 · 도구 호출 실시간) | 검사 에이전트 > 에이전트 실행 | 1 |
| 4 | **멀티모달 도구** (Grad-CAM/ROI 이미지 해석) | 라이브 실행 중 `inspect_image` | 1 |
| 5 | **결함 Q&A 에이전트** (read-only 도구로 직접 조회) | 검사 에이전트 > 결함 Q&A | 1 |
| 6 | **멀티에이전트 위임** (inspection → MLOps) | 라이브 실행 중 `escalate_to_mlops` | 2 |
| 7 | **MLOps 에이전트 + 자율 모드** (자동/승인) | MLOps 콘솔 > MLOps 에이전트 | 2 |
| 8 | **HITL 승인 게이트** (High-risk 도구 승인/반려) | MLOps 콘솔 > 모델 운영 콘솔 "승인 대기" | 3 |
| 9 | **사람 피드백 루프** (반려 이력을 에이전트가 학습) | 같은 케이스 재실행 시 evidence에 반영 | 3 |
| 10 | **RAG 학습 루프** (확정 사례 → RAG 적재 → 재검색) | 데이터 관리 > rag_documents | 3 |
| 11 | **트레이스 영속화** (모든 에이전트 판단 기록) | 데이터 관리 > agent_traces | 4 |
| 12 | 자동 감시 / 인수인계 / Copilot (보조) | 실시간 검사 / Alert Center | 4 |

## 1. 사전 준비 (데모 시작 2분 전)

1. **백엔드 기동** — `LUXIA_API_KEY`가 `.env`에 설정돼 있어야 실제 LLM/임베딩이 동작한다(없으면 룰 폴백으로 떨어져 "에이전트가 생각하는" 그림이 안 나온다).
   ```bash
   python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
   ```
   - 부팅 직후 백그라운드 스레드가 **RAG 벡터 인덱스를 자동 시드**한다(로그 `RAG index seed: {...}`). 시드가 끝나기 전엔 RAG가 룰 라이브러리로 폴백하므로, **시연 1~2분 전에 띄워 인덱스를 채워둔다.**
2. **프론트엔드 기동** — `VITE_API_BASE_URL=http://127.0.0.1:8000 npm run dev`
3. **설정 탭 → `Agent LLM 분석` ON** ⚠️ *가장 중요.* 이게 꺼져 있으면 모든 에이전트가 룰 폴백 메시지만 낸다. 데모 전 반드시 확인.
4. **데모 데이터 시드** — 빈 DB라면 한 번 시드해 리스크 큐·승인 대기·드리프트 이력을 채운다.
   ```bash
   curl -X POST http://127.0.0.1:8000/api/v1/demo/seed -H 'Content-Type: application/json' -d '{}'
   ```
   - 시드 시나리오에 **ETCH-02 Scratch** 케이스가 포함돼 있어, 아래 "반복성 결함" 스토리가 자연스럽게 성립한다.
5. (선택) **자동 감시 몇 틱** 돌려 라이브 데이터가 흐르는 인상을 준다 — 실시간 검사 탭의 스트림 `재개` 버튼.

> **Rate limit 주의:** 짧은 시간에 라이브 실행을 연속으로 누르면 LLM 게이트웨이가 429를 낼 수 있다. 각 에이전트 실행 사이에 결과를 설명하며 텀을 둔다(코드가 폴백 처리하지만 데모 그림이 흐려짐).

## 1.5. 소요 시간 (한눈에)

**전체 8~12분, 현실적으로 ~10분.**

| 막 | 내용 | 소요 |
|----|------|------|
| Act 0 | 무대 세팅 (검사 스트림 + 1회 실행) | ~0.5분 |
| Act 1 | 단일 이상 대응 (RAG 근거 → 라이브 실행 → 결함 Q&A) | 3~4분 |
| Act 2 | 멀티에이전트 위임 + MLOps 자율모드 | 2~3분 |
| Act 3 | 승인 반려 → 피드백 재실행 → RAG 학습 적재 | 2~3분 |
| Act 4 | 마무리 (테이블 3개 + 클로징) | ~1분 |

**시간을 좌우하는 변수 — 라이브 실행 대기시간:**
- 실제 LLM + 도구 다중 호출이라 라이브 실행 1회는 **10~20초**.
- **위임(escalate_to_mlops)** 은 MLOps 에이전트의 중첩 루프(약 8개 도구 호출)까지 돌아 **20~40초**.
- 데모 중 라이브 실행은 **3~4회**(Act1 / Act2 위임 / Act3 재실행). 연속 클릭 시 429(rate limit) 위험 → 사이에 텀을 두고, **그 대기시간을 멘트로 채운다**(대기 = 설명 시간).

**시간이 빠듯하면:**
- **30초 버전(§5):** 라이브 실행 1회 → 반려 → 재실행. 판단·협업·개입·학습이 모두 포함.
- **5분 압축:** Act 1(라이브 실행 1회) + Act 2(위임) + Act 3(반려→재실행)만. Act 0·4 생략.

**권장 슬롯:** Q&A 포함 **12~15분**을 잡고 실제 시연은 10분 내외로 운영. 사전에 RAG 인덱스 시드 + `Agent LLM 분석` ON만 확인하면 대기시간 사고를 크게 줄인다.

## 2. 데모 흐름 (총 8~12분)

### Act 0 — 무대 세팅 (30초)
- **실시간 검사 > 검사 결과** 탭에서 시작. 웨이퍼 맵 / Grad-CAM 오버레이 / 계측값이 흐르는 운영 화면을 보여준다.
- 멘트: *"이건 검사 결과 화면입니다. 핵심은 여기서 끝나지 않고, 이상 징후가 보이면 **에이전트가 이어받아 판단하고 조치**한다는 점입니다."*
- `1회 실행` 버튼으로 새 검사를 한 건 생성 → 토스트로 결함/리스크가 뜬다.

### Act 1 — 단일 이상 대응: 개별 에이전트의 추론 (3~4분)

**1-a. 리스크 큐에서 케이스 선택**
- **실시간 검사 > 검사 에이전트** 서브탭으로 이동. 왼쪽 **리스크 큐(Medium/High)** 에서 **ETCH-02 Scratch** 케이스 선택.
- 검사 개요(웨이퍼 맵·Grad-CAM·리스크 게이지·계측값)와 **AI 추천(추정 원인 / 권장 액션)** 이 뜬다. 우상단 칩: `근거: RAG + 계측 룰`.

**1-b. RAG 근거 열어보기 (기능 #2)**
- 추정 원인 카드의 **근거 보기**(EvidenceModal)를 연다 → 에이전트가 **벡터 RAG로 검색한 과거 유사 사례**가 유사도 점수와 함께 나온다.
- 멘트: *"이 추천은 임의 생성이 아니라, 질의를 임베딩해 과거 사례 코퍼스에서 코사인 검색 후 rerank한 결과입니다. 메인 검사 플로우가 실제 벡터 RAG를 씁니다."*

**1-c. 에이전트 라이브 실행 (기능 #3, #4) — 하이라이트**
- 우측 하단 **에이전트 실행** 패널의 **`라이브 실행`** 버튼 클릭.
- 실시간으로 펼쳐지는 것을 같이 읽어준다:
  - `설비 이력 조회`(get_equipment_history) → *"같은 설비에서 24h 내 동일 결함 N회 → 반복성 판정"*
  - `계측 추세 조회`(get_metrology_trend) → *"단발 스파이크인지, 계속 밀리는지 구분"*
  - `웨이퍼 이미지 분석`(inspect_image, **멀티모달**) → Grad-CAM hotspot 위치 해석
  - 마지막에 **최종 판단**이 토큰 스트리밍으로 작성됨.
- 멘트: *"사람에게 '이력 확인해보라'고 시키는 게 아니라, **에이전트가 직접 DB를 조회해 자기 플레이북을 실행**합니다. 그리고 그 조회 결과를 근거로 인용해 판단합니다."*

**1-d. 결함 Q&A 에이전트 (기능 #5)**
- 같은 화면의 **결함 Q&A**에 입력: *"이 설비에서 같은 결함 최근에도 났어?"*
- 에이전트가 `get_equipment_history`를 호출(툴 칩이 뜸)하고 → 실제 수치로 답한다.
- 멘트: *"챗봇이 정적 텍스트로 답하는 게 아니라, 답에 필요한 데이터를 **도구로 직접 조회**해 근거와 함께 답합니다(환각 방지)."*

### Act 2 — 멀티에이전트 협업: 위임 (2~3분)

**2-a. 위임이 일어나는 라이브 실행 (기능 #6) — 하이라이트**
- 반복성이 강한 ETCH-02 Scratch 케이스에서 `라이브 실행`을 (다시) 누른다.
- 에이전트가 반복성을 확인한 뒤 **`MLOps 에이전트로 위임`**(escalate_to_mlops) 칩을 띄운다.
  - 펼쳐보면 MLOps 에이전트가 **자기 루프**(get_mlops_state, get_metrology_trend, get_equipment_history)를 돌려 fleet 판단(재학습 권고 → 승인 대기)을 돌려준 것을 확인.
- 최종 판단: *"설비 점검(개별 조치) + 재학습 승인 검토(fleet 조치)"* 로 **두 층위가 종합**된다.
- 멘트: *"개별 웨이퍼 차원을 넘는 문제라고 판단되면, 에이전트가 **다른 에이전트를 호출**합니다. 한 화면에서 '에이전트가 에이전트를 부르는' 핸드오프가 보입니다. 위임은 단방향이라 무한 재귀가 없습니다."*

**2-b. MLOps 에이전트 단독 + 자율 모드 (기능 #7)**
- **MLOps 콘솔 > MLOps 에이전트** 서브탭. 상단 **자율 모드** 토글을 보여준다:
  - `승인 요청` — 재학습 권고를 **승인 대기열**에 등록(기본).
  - `자동 실행` — 사람 승인 없이 즉시 재학습 실행.
- 모드를 골라 에이전트를 실행 → fleet 성능(F1)·드리프트·추세를 인용한 판단이 스트리밍된다.
- 멘트: *"같은 에이전트가 **자율성 수준을 다이얼처럼** 조절합니다. 안전이 중요한 fab에서는 '승인 요청'으로, 신뢰가 쌓이면 '자동 실행'으로 — 사람과 자동화의 경계를 운영자가 정합니다."*

### Act 3 — HITL + 학습 루프: 시스템이 사람에게 배운다 (2~3분)

**3-a. 승인 게이트 (기능 #8)**
- **MLOps 콘솔 > 모델 운영 콘솔**의 **`승인 대기 · Pending Approvals`** 패널.
- Act 2에서 에이전트가 올린 **재학습 권고**가 대기 중. 여기서 **반려**(또는 승인)한다.
- 멘트: *"High-risk 도구(긴급 알림·재학습)는 에이전트가 바로 실행하지 못하고 **사람 승인 게이트**를 거칩니다. 반려해 보겠습니다."*

**3-b. 사람 피드백 루프 (기능 #9) — 하이라이트**
- **검사 에이전트**로 돌아가 같은 **ETCH-02 Scratch** 케이스를 다시 `라이브 실행`.
- 이번엔 에이전트의 근거(evidence)에 **"과거 사람 피드백 — 반려"** 가 반영되고, 판단이 달라진다(같은 권고를 반복하지 않고, 추가 조회 후 검토 큐로 넘기는 식).
- 멘트: *"방금 반려한 결정을 에이전트가 **기억**합니다. 사람이 'No'라고 한 조치를 그대로 반복하지 않고, 반려 사유를 근거로 다른 판단을 내립니다 — 에피소드 기억 기반 보정입니다."*

**3-c. RAG 학습 루프 (기능 #10) — 하이라이트**
- 검사 에이전트에서 케이스를 **`조치 완료(approved)`** 로 리뷰 처리(권장 액션 실행 버튼 또는 리뷰 결정).
- **데이터 관리 > rag_documents** 테이블을 연다 → `LEARNED-...` / `source: engineer_confirmed` 문서가 **새로 적재**된 것을 보여준다.
- 다시 **검사 에이전트**에서 유사한 새 검사를 만들고 RAG 근거를 열면 → **방금 확정한 사례가 검색 결과 상위에** 뜬다(`[운영 학습]` 표시).
- 멘트: *"엔지니어가 확정한 사례가 즉시 RAG 지식베이스에 임베딩되어 적재되고, **다음 유사 상황에서 검색됩니다.** 운영할수록 코퍼스가 똑똑해지는 닫힌 학습 루프입니다."*

### Act 4 — 마무리: "모든 것이 기록되고 학습된다" (1분)
- **데이터 관리** 탭에서 세 테이블을 빠르게 짚는다:
  - `agent_traces` — 모든 에이전트의 판단·도구 호출 전 과정이 감사 가능하게 기록됨.
  - `pending_approvals` — 승인/반려 게이트의 이력.
  - `rag_documents` — 시드 코퍼스 + 운영 중 학습된 사례.
- (선택) **Alert Center** / 인수인계 Daily Report / Copilot 요약으로 "교대·라인 단위 운영 통합"을 한 줄 언급.
- **클로징 멘트:** *"단일 이상 한 건이 들어오면 — 에이전트가 판단하고, 증거를 RAG로 찾고, 멀티모달로 이미지를 보고, 필요하면 다른 에이전트에 위임하고, 사람 승인을 받고, 그 결과로 다시 학습합니다. 이게 DNN 한 개가 아니라 **에이전트 운영 시스템**입니다."*

## 3. 기능 → 화면/조작 빠른 참조표

| 기능 | 경로 | 조작 |
|------|------|------|
| 벡터 RAG 근거 | 실시간 검사 > 검사 에이전트 > AI 추천 | 추정 원인 카드 "근거 보기" |
| 검사 에이전트 라이브 | 실시간 검사 > 검사 에이전트 > 에이전트 실행 | `라이브 실행` |
| 결함 Q&A | 동상 > 결함 Q&A | 질문 입력 |
| 멀티에이전트 위임 | 라이브 실행 결과 | `MLOps 에이전트로 위임` 칩 펼치기 |
| MLOps 에이전트 / 자율모드 | MLOps 콘솔 > MLOps 에이전트 | 자율 모드 토글 + 실행 |
| 승인/반려 | MLOps 콘솔 > 모델 운영 콘솔 | 승인 대기 패널 |
| 사람 피드백 반영 | 검사 에이전트 (같은 케이스 재실행) | `라이브 실행` |
| RAG 학습 적재 | 데이터 관리 > rag_documents | 리뷰 `조치 완료` 후 확인 |
| 트레이스/감사 | 데이터 관리 > agent_traces | 테이블 열람 |

## 4. 트러블슈팅 / 폴백

| 증상 | 원인 | 대응 |
|------|------|------|
| 에이전트가 "룰 기반 판단 — LLM 미사용"만 출력 | 설정 `Agent LLM 분석` OFF 또는 `LUXIA_API_KEY` 미설정 | 설정에서 토글 ON / `.env` 키 확인 후 백엔드 재기동 |
| RAG 근거가 빈약/룰 라이브러리로 보임 | 시작 직후 벡터 인덱스 시드 미완 | 1~2분 대기, 또는 `python scripts/build_rag_index.py`로 선시드 |
| 라이브 실행이 멈춤/오류 | LLM 게이트웨이 429(rate limit) | 실행 간격을 두기, 잠시 후 재시도(코드가 폴백 처리) |
| 리스크 큐가 비어 있음 | DB 미시드 | `POST /api/v1/demo/seed` |
| 위임/승인 대기가 안 보임 | 에이전트가 아직 fleet 위임을 안 함 | 반복성이 강한 ETCH-02 Scratch 케이스로 라이브 실행 |

## 5. 30초 엘리베이터 버전 (시간 없을 때)

1. **검사 에이전트 > 라이브 실행** 한 번 — 도구 호출 → 위임 → 최종 판단까지 한 흐름.
2. 그 위임이 만든 **승인 대기**를 모델 운영 콘솔에서 **반려**.
3. 같은 케이스 **재실행** → 에이전트가 반려를 기억해 판단이 바뀐다.

→ "판단·협업·사람 개입·학습"이 30초에 다 들어간다.

## 6. 강조할 차별점 (심사/질의 대비)

- **RAG는 화면용 장식이 아니다:** 메인 검사 플로우가 embed→cosine→rerank 벡터 검색을 쓰고, 운영 중 확정 사례가 다시 적재되는 **닫힌 루프**다.
- **멀티에이전트가 실재한다:** inspection·MLOps 두 프로필이 각자 도구셋/시스템 프롬프트를 갖고, 위임(escalate)으로 협업한다(단방향, 재귀 안전).
- **자율성은 다이얼이다:** 같은 에이전트가 알림/승인/자동 모드로 사람-자동화 경계를 조절한다.
- **사람 피드백이 닫힌다:** 승인/반려가 단순 상태 변경에 그치지 않고 다음 판단의 컨텍스트로 들어간다.
- **모든 판단이 감사 가능하다:** agent_traces에 도구 호출·메시지·최종 판단 전체가 남는다.
